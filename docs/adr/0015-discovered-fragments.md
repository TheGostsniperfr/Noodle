# ADR-0015 · Adapters write fragments; the curated model matches them

- Status: Accepted
- Date: 2026-09-30
- Extends: ADR-0002 (model, view, layout), ADR-0005 (Git is the source of truth),
  ADR-0007 (contract files)

## Context

Every fact in a model is written by hand or by an AI agent reading the code. A measured
diagram session spent about 41 % of its cost on that reading, and the result drifts as
soon as the system changes: nothing says the diagram is stale. Static discovery from
Kubernetes manifests, and later Terraform, the live API or scanners (security, cost,
alerting), can produce most of those facts for free. They must not overwrite the curated
model, which carries what code cannot: names a reader understands, zones, what to leave
out, the question a view answers.

## Decision

- **An adapter produces a fragment**, never edits the model. A fragment is a new contract
  `kind: Fragment` in `noodle/v1alpha1`: the Model's elements, connections and references,
  plus `provenance: {adapter, source, ref, observedAt}` on the fragment and `src` (file and
  line, or API object) on every item. Adapters are independent packages behind one Go
  interface and a registry; a new adapter adds a package, not a change to the core.
- **Discovered IDs are deterministic**, derived from the source:
  `k8s:<namespace>/<kind>/<name>`, later `tf:<address>`. Rerunning an adapter on the same
  input gives the same fragment, byte for byte.
- **The curated model links to them with `matches`**: an element lists the discovered IDs
  it stands for (`matches: [k8s:prod/deployment/api, k8s:prod/service/api]`). Merging
  fills fields the curated element leaves empty (ports, tech) and never overrides one it
  sets. Discovered connections between matched elements map onto curated IDs.
- **Drift is a report, not a failure**: discovered but unmatched, matched but gone,
  `planned` and still absent, connections found but not modelled. `noodle drift` prints
  it; a team decides later whether CI fails on it.
- **Enrichment modules add facets**, keyed by element ID, in their own fragments
  (`facets: {security: …, cost: …}`). They never add fields to the core element. A view
  selects the facets it shows. Facets are reserved by this ADR and specified by the first
  module that needs one.
- **Storage is files.** Fragments live in `<system>/discovered/<adapter>-<source>.yaml`,
  are regenerated by the adapter and are not committed (ADR-0005: generated artifacts).
  The merged model is a directed graph built in memory for each command. It is not a DAG:
  architectures have cycles. One package, `internal/graph`, owns merge and queries
  (lookup, neighbours, paths, drift), so another backend could replace it without
  touching the adapters.

## Revisit the storage when

- live overlays (L5) need history over time, which ADR-0005 already keeps out of Git;
- loading the fragments on every command becomes slow;
- cross-module queries outgrow what the CLI and the MCP server expose.

A graph database (Neo4j, as Cartography uses) is the likely answer then, behind
`internal/graph`.

## Consequences

- An AI agent reads a compact fragment and writes only the curated part.
- Every discovered fact has a source a reviewer can open.
- `matches` and `Fragment` are additions to `v1alpha1`: no version bump.
- A curated element without `matches` stays valid: discovery is optional.
