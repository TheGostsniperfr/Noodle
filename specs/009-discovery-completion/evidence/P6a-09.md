## Findings

- `internal/adapter/k8s/secretendpoint_test.go:62` and `:92`: the `-env` and `-ignores-password` fixtures contain no `Secret`, so `NotContains(endpointValue / encoded / "hunter2")` would still pass if the implementation copied Secret data into the fragment. **Fix:** append a `kind: Secret` `db` in `prod` to both fixtures, with `data: {DB_URL: <encoded>, PASSWORD: <encoded>}` and a `stringData` value, so the leak check has something to catch.
- `secretendpoint_test.go:75-91`, `-externalsecret`: there is no Secret value in the input, so the follow-up's "no Secret value and no base64 form" check is vacuous here as well. **Fix:** add the written `Secret` `db` with data to the fixture. The ExternalSecret then writes a Secret that is also present with values, and the test proves the values are not read. Also assert that the template value `jdbc:postgresql://{{ .host }}/app` is absent. I checked by hand that it is absent today: `grep -c 'jdbc:postgresql'` on the discover output = `0`.
- `internal/adapter/k8s/secretendpoint.go:75-77` together with `unresolved.go:20` breaks FR-017's "one `secret-endpoint` entry per Secret". `value` is `<name>/<keys>` with no namespace. Two different Secrets with the same name and keys therefore merge into one entry under `u.add`'s `kind + value` key. Reproduced: `prod/api` reads `db` through envFrom (the Secret holds `DB_URL`) and `staging/api` reads `secretKeyRef {name: db, key: DB_URL}`. `noodle discover k8s -` then prints one entry `{about: ['k8s:prod/deployment/api', 'k8s:staging/deployment/api'], kind: secret-endpoint, value: db/DB_URL}`. **Fix:** put the namespace in the value or the merge key (e.g. `prod/db/DB_URL`, which needs the spec scenario and the golden updated through the amendment table), and add a subtest with two namespaces.
- `secretendpoint_test.go:92-99`: in `-ignores-password`, the `PASSWORD` key contains none of the address words, so that half proves nothing about the credential filter. Only `SMTP_SERVER_PASSWORD` exercises `credentialWords`. This breaks no criterion; noted for completeness.
- `schemas/v1alpha1/fragment.schema.json:109`: adding `secret-endpoint` to the `unresolved.kind` enum is decided by ADR-0018 (line 46). It is not listed in plan 009's "Packages and files" table, which names only `object` for this schema, and there is no version bump (C06). This matches the ADR-0028 precedent for `object` in v1alpha1, so it is not a blocker. The plan table should still list it.
- Removal check: dropping `secretEndpoints(idx, uses, u)` from `k8s.go:34` fails `-env`, `-envfrom` and `-externalsecret`, because their `want` lists are non-empty. The `Equal` assertions do catch a reverted feature. Only the never-read-values half is untested.
