## Review beyond the contract

- **Would the test catch the feature being reverted?** Yes. `internal/adapter/k8s/example_test.go:64-87` does three things:
  1. It encodes the fragment from the manifests.
  2. It stages `list.yaml`, which has a top-level `kind: List`, at the same relative path and encodes that fragment too.
  3. It compares the two with `assert.Equal` and checks that `k8s:prod/deployment/worker` is present.

  The List expansion lives in `decode.go:172` (`strings.HasSuffix(kind, "List")` → `itemNodes`). If it were removed, the List would count as one object of kind `List`, the fragment would have no workloads, and both the `Equal` check and the `Contains` check would fail.
- **Can `list.yaml` drift from the manifests?** No, not silently. Line 75 checks that the committed `list.yaml` equals `listFromManifests(platform.yaml)`. The test only rewrites the file when `UPDATE_LIST` is set.
- **Is the verify step guarded against a tautology?** Yes. The two runs read different files: one plain YAML file with three documents, and one `kind: List` file with indented items.
- **Is `docs/features.json` untouched (C12)?** Yes. The P6a-04 entry is unchanged in the diff and still has `"passes": false`.
- **Does the diff relax a lint rule (C04)?** No. Nothing in the k8s adapter or the example does.

## Findings

None of these breaks a criterion. They are follow-ups:

- **`examples/discovery-k8s/list.yaml` is a synthetic List, not real `kubectl get -o yaml` output.** It has no `status`, `managedFields`, `uid`, `resourceVersion` or `creationTimestamp`; `grep -cE "managedFields|resourceVersion|uid:|status:"` returns `0`. FR-009 only asks for "the same objects wrapped as a List", so the criterion holds. It does not prove that live-cluster noise leaves the fragment unchanged. Fix: add a second List fixture that carries these server-side fields and assert the same fragment.
- **`internal/adapter/k8s/example_test.go:79-83` stages `list.yaml` as `examples/discovery-k8s/manifests/platform.yaml`** in a temporary directory. The file path in the fragment's `src` entries therefore matches. This is the only way a byte-equal comparison can hold, because `src.file` is part of the fragment. Even so, the test never discovers from a file actually named `list.yaml`. Fix: record this interpretation in plan 009 or the test's comment, so later readers know it is deliberate.
