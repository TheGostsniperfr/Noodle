# Plan 011 · Own SVG and PNG renderer

Spec: [`spec.md`](spec.md). Decisions: ADR-0033, ADR-0034, ADR-0035, ADR-0036;
clarifications 1 to 5 of the spec, answered.

## Approach

The resolver and `internal/house` already compute every position: `house.DrawnPath`
gives an edge's full path, `CardLayout` the rows of a card, `NodePillRect` the pill.
What is missing is a place where the drawn result exists as data. Today it only exists
as draw.io XML, printed while it is decided.

```
resolve ──▶ diagram.Spec ──▶ scene.Build(spec, theme) ──▶ scene.Scene
                  │                                  ├─▶ render/drawio  (.drawio)
                  └─▶ lint (reads house + font)      ├─▶ render/svg     (.svg)
                                                     └─▶ render/png     (.png)
```

- **Scene** (ADR-0033): an ordered list of elements: `Rect`, `Text`, `Path`, `Edge`,
  `Image`, `Pill`, `Group`. Each has the id the draw.io cell has today, its rectangle,
  a resolved `Style` (fill, stroke, width, dash, radius, opacity, hatch) and, for text,
  lines of runs (`Text`, `Bold`, `Color`, `Size`) parsed once from the markup.
  `Edge` keeps source, target, exit and entry fractions and the label fraction for
  draw.io, and the full path for the others.
- **draw.io writer**: `render.go`, `sequence.go` and `matrix.go` move to
  `internal/render/drawio` and read the scene. The refactor comes first, with every
  `.drawio` byte-identical (FR-007).
- **Font** (ADR-0034): `assets/fonts/` holds JetBrains Mono NL Regular and Bold 2.304
  and `OFL.txt`. `internal/font` parses them with `golang.org/x/image/font/sfnt`, gives
  advances and coverage to `house` and the lint, and writes subsets. The lint rule
  `glyph_coverage.go` is new; `house.ExportTextWidth` becomes the sum of advances,
  floored at `ExportCharWidthEm` per rune.
- **SVG writer**: one `<g id=…>` per element, styles as attributes, text as `<text>` with
  `<tspan>` runs, the two font subsets in a `<style>` block, icons inlined as nested
  `<svg>` with ids prefixed by the element id. Rounded corners and jump arcs at edge
  crossings are computed in the scene, so the PNG draws the same.
- **PNG writer** (ADR-0035): `x/image/vector` fills; a stroker in `internal/render/png`
  turns paths, corners, dashes and arrow heads into polygons; `x/image/font/opentype`
  draws text; a small SVG reader draws icons (paths, basic shapes, transforms, fills,
  `<style>` class rules, linear gradients). The three icons using `clipPath`, `mask` or
  gradients beyond that are checked first and re-curated if needed.
- **Animation** (FR-005): `-animate` adds a CSS keyframe on `stroke-dashoffset` to
  traffic edges, direction from the path order, which runs from the opening side.
- **Draft** (FR-006, ADR-0036): `lint.Finding` has only `Where`, `Msg` and `Warn`; in T03
  it gains `Rule` (one id per rule file, 19 with `glyph_coverage`) and `Rect`.
  `-draft` turns findings into scene elements drawn last, plus a banner.
- **CLI**: `-o` picks the writer by extension; `-scale` (default 2) for PNG; `-animate`;
  `-draft`. The Makefile's `examples` target renders `.svg` and both PNGs and compares
  them with the committed files.

Contracts read: `diagram.Spec` (internal), model, view and layout schemas unchanged.
Contracts written: none new; the SVG is an output, not a contract (C06).

## Alternatives set aside

- **Parse the `.drawio` file and draw it**: it carries draw.io's own routing and HTML
  labels, and would make noodle a draw.io reimplementation.
- **Rasterize the SVG with a Go SVG library** (`oksvg`, `canvas`): neither covers text
  with an embedded font well, and both would be one more dependency; drawing the scene
  directly is simpler than parsing back what noodle just wrote.

## Risks

| Risk | Mitigation |
|---|---|
| The scene refactor changes a `.drawio` byte | T02 lands alone, with `TestExamples_DrawioCurrent` green before any new writer |
| draw.io drew things noodle never computed (rounded edge corners, jump arcs, label background) | computed in the scene in T05, compared visually with the draw.io PNG on every example in the PR |
| Anti-aliased text in Go looks worse than a browser's | hinting off, gamma as browsers apply it; judged on the PNGs in the T06 PR before the examples switch |
| An icon uses SVG the reader does not draw | T07 renders every icon in both variants and fails on an unknown element; re-curate rather than grow the reader |
| Every example image changes at once | one PR per wave, each with before/after crops (C13) |
| Hand-made subsetting corrupts a font | the subset is parsed back by `sfnt` in tests, and opened by a browser in the T06 review |
